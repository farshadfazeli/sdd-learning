SECTION 02 · TOOLS

انواع SDD و ابزارهای آن

همهٔ تیم‌ها یک شکل از Spec-Driven Development را اجرا نمی‌کنند. سه الگوی رایج را بشناس.

سه رویکرد اصلی

Spec-first

مشخصات پیش از کدنویسی نوشته و بررسی می‌شود.

Spec-anchored

مشخصات در کنار کد حرکت می‌کند و مرجع تصمیم‌های مهم است.

Spec-as-source

مشخصات مانند منبع اصلی رفتار سیستم عمل می‌کند.

دستورهای GitHub Spec Kit

این دستورها معمولاً به‌صورت workflow یا slash command استفاده می‌شوند و هرکدام یک مرحله از تبدیل ایده به اجرای قابل بررسی را مدیریت می‌کنند.

Commandکاربرد فارسیEnglish purpose
/speckit.constitutionاصول، قوانین کیفیت و محدودیت‌های ثابت پروژه را تعریف می‌کند.Defines project principles, quality rules, and constraints.
/speckit.specifyایده یا نیازمندی خام را به specification قابل بررسی تبدیل می‌کند.Turns a raw requirement into a reviewable specification.
/speckit.clarifyابهام‌های specification را پیدا می‌کند و سؤال‌های روشن‌کننده می‌پرسد.Finds ambiguity and asks focused clarification questions.
/speckit.planبر اساس specification، طراحی فنی و مسیر اجرا را آماده می‌کند.Creates the technical design and implementation approach.
/speckit.tasksطراحی را به taskهای کوچک، مرتب و قابل انجام تقسیم می‌کند.Breaks the design into ordered, actionable tasks.
/speckit.implementtaskها را اجرا می‌کند و تغییرات کد را می‌سازد.Executes the tasks and builds the code changes.
/speckit.analyzeسازگاری specification، طراحی، taskها و کد را بررسی می‌کند.Checks consistency across the spec, design, tasks, and code.
/speckit.checklistبرای کنترل کامل بودن و کیفیت خروجی checklist تولید می‌کند.Generates a checklist for completeness and quality.

نکته: نام دقیق commandها ممکن است با نسخه یا تنظیمات workflow تغییر کند؛ مستندات نسخهٔ استفاده‌شده را بررسی کنید.
